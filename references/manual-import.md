# 人工下载与导入

## 人工队列

每条记录提供：

- 记录 ID 或 Excel 行；
- 标题、DOI、年份、来源、出版社；
- DOI landing page；
- 推荐渠道；
- 预期文件名；
- 人工状态和备注。

## 普通 PDF 导入

1. 用户通过合法渠道下载到独立 inbox；
2. 先检查 `%PDF-` 签名和可解析页数；
3. 提取前若干页文字；
4. 优先匹配 DOI并核对题名；无DOI匹配时，必须有按原词序出现的完整标题（容忍换行、连字符和连字）且至少5个有效词，不能仅凭散落词语的覆盖率。书目有DOI而候选前两页只有其他DOI时拒绝自动放行，交人工核对；
5. 多个候选接近时标记 `ambiguous_match`；
6. dry-run 列出匹配结果；
7. 确认后复制到 `.part` 文件；
8. 验证哈希后原子重命名；
9. 不删除 inbox 原件；
10. 重新审计。

单篇收件与普通导入/审计使用同一PDF身份规则。重要批次仍须独立核对首页题名、作者与期刊，并将正式副本SHA-256与预先检查的来源文件比较；与既有语料重复的哈希不能冒充新论文。发现误入库时，保留原回执，记录纠正决定，将错误副本移入隔离目录后再重新导入，不直接覆盖正式文件。

## 图像型 PDF

没有可提取文字的 PDF 不应被普通导入器自动接受。视觉审批 manifest 至少包括：

- `source_path`
- `expected_filename`
- `record_id` / `excel_row`
- `title`
- `doi`
- `visual_approved=true`
- `approval_evidence`

审批事件还应记录页数、字节数和 SHA-256。审计时只有事件哈希与当前文件一致才承认。

## 隔离

视觉审批事件可通过`audit --visual-approvals FILE.jsonl`显式传入。若后续普通审计或本地浏览器收件也必须保留同一审批，在私有项目配置的`[identity]`下设置`visual_approval_files = ["relative/path/to/events.jsonl"]`。路径相对配置文件解析；配置的证据文件缺失时停止，而不是默默撤销审批。保存配置修改前的原版本。

该设置只复用已记录的文件名与SHA-256匹配审批，不会自动批准新文件。审批必须说明实际核验者（例如AI，而不是虚构人类）、题名、作者、来源、页码、原始机器失败和所看原件图像。没有开放许可时，不推断可公开再分发。首次配置后，通过实际`audit`入口确认状态和哈希，再开始后续处理。

HTML 假 PDF、损坏容器、错误论文和歧义匹配进入 quarantine 或保留在 inbox；不得覆盖正式语料中的同名文件。
