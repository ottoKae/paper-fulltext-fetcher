# 全文获取工作流

## 适用时机

当任务涉及从书目清单建立全文语料、补齐缺失论文、恢复中断任务或报告全文覆盖率时读取本文件。

## 阶段门

### G-1：首次运行

- 用 `self-test` 在合成数据上验证本地安装；
- 用 `init` 创建相对路径配置和工作目录；
- 用 `doctor` 区分环境就绪与项目就绪；
- 用 `inspect-input` 确认工作表和列名映射；
- 只有 `ready_for_audit=true` 后才处理真实语料。

### G0：冻结输入和口径

- 记录输入文件、工作表、记录数和 SHA-256；
- 不修改源书目；
- 规定 PDF、全文 XML 和扫描型 PDF 的认可标准；
- 规定稳定记录 ID 和预期文件名；
- 建立独立输出目录。

### G1：本地审计

- 枚举现有 PDF/XML；
- 检查容器签名、文件大小和可解析性；
- 用 DOI 或标题确认身份；
- 检查重复内容、孤立文件和同一记录的多个文件；
- 生成 remaining queue。

### G2：元数据修复

- 规范化 DOI，去掉 `doi.org` 前缀和查询参数；
- 通过标题、年份、来源和作者对候选 DOI 评分；
- 只有高置信度候选可以自动提升；
- 保留候选来源和分数，不回写源书目。

### G3：开放发现

顺序建议：

1. Unpaywall；
2. OpenAlex；
3. Crossref link/TDM 元数据；
4. PMC 或其他学科知识库；
5. 机构知识库和作者接受稿。

发现与下载分开。发现阶段只生成候选、许可线索和来源，不直接把候选放入正式语料。

### G4：官方 API/TDM

- 确认 API 产品、机构 entitlement 和研究用途；
- 只用环境变量传递凭据；
- 先对一篇明确订阅或 OA 文章测试；
- 验证返回的是全文而非摘要；
- 按官方速率限制执行，并保留请求结果类别。

### G5：可见浏览器辅助

- 用户亲自启动浏览器并完成登录和挑战；
- 调试端口只监听 `127.0.0.1`；
- 先做只读 probe，再做单篇 smoke；
- 默认单并发和 60–90 秒随机间隔；
- 不导出 Cookie，不在无头浏览器中自动登录；
- 明确未订阅的文章转人工/OA，不重复请求。

### G6：人工队列

人工队列至少包含：记录 ID、标题、DOI、年份、出版社、预期文件名、官方落地页和建议渠道。人工渠道包括学校数据库、图书馆全文传递、馆际互借、作者主页和联系作者。

### G7：导入与终审

- 文件进入 inbox 后先 dry-run；
- 验证容器和身份后原子复制；
- 不删除源文件；
- 扫描型 PDF 使用带哈希的视觉审批事件；
- 每批导入后重新审计；
- 最新审计是唯一进度真值。

### G8（可选）：本地语料准备

- 仅从最新审计中登记已经通过容器、身份和哈希验证的 PDF/JATS XML；
- 保持源全文只读，以稳定 `study_id`、SHA-256 和相对路径建立注册表；
- 先运行小样本 benchmark，再进行 base 批处理；
- 生成 Docling JSON、Markdown、带页码/坐标或 XPath 的证据块与 append-only manifest；
- 质量评估后，只对失败或低质量 PDF 进入 OCR 重试队列；
- 下游使用前再次核验源文件、派生文件、定位器和配置哈希。

G8 只负责让全文可搜索、可定位、可审计，不负责判断纳入范围，也不抽取、分类或汇总综述变量。

## 运行更新模板

开始联网前向用户说明：

- 处理的记录数与出版社；
- 将访问的服务/域名；
- 使用 OA、官方 API/TDM 还是已登录浏览器；
- 并发、间隔、预计批次；
- 输出目录和事件日志；
- 熔断条件。

完成后报告：成功、已存在、无订阅、无 OA、权限不足、限流/挑战、身份错误和人工待办数量。
